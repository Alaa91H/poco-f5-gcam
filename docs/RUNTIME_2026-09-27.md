## Motion stabilization correction

Inspection of the installed DEX found that `rdw.j()` selects only Pixel device
profiles and throws for an unrecognized device. The motion stabilization
provider queries `camera.micro_prestab` and `camera.micro_ls_always_prestab`
with OR semantics. Both must be disabled to select the existing path without
this optional stabilizer.

The compatibility flag guard now returns false for these two exact names in
both `klm.q()` and `klm.x()`. Other motion features and similarly named flags
continue into the original implementation. No substitute Pixel calibration
profile is fabricated. This intentionally disables the affected motion-photo
stabilization feature in the POCO compatibility build.

Validation completed:

- All 81 Python tests passed. The new regression failed for both flags in both
  methods before the fix, then passed after it.
- The modified real `klm` class extracted from the installed APK assembled
  successfully with the pinned smali 3.0.10 toolchain.
- A standalone DEX exercised the generated guards on the connected Android
  runtime: all 10 expected results matched, including unrelated-flag fallthrough
  and the existing accelerator rejection.

At the time of this device investigation, the updated full APK had **not** been
built, signed, installed, or validated. Subsequent CI delivery is recorded in
GitHub Actions and does not change the device-validation result here.
The standalone guard check is not an application startup or camera test.
